二、七虾定义

1. 门虾 gate — 纯对话界面

配置项值
模型anthropic/claude-haiku-4-5
Sandboxoff (需完整文件访问)
Workspace~/CC/
delegationModeprefer (强制偏好委托)

SOUL.md 铁律（仅3条）：

  1. 能 1-2 句话回答的 → 直接答 (S级)
  2. 其他的 → sessions_spawn(agentId: "plan") → 立即回复「收到，策虾在处理了」
  3. 绝不做任何需要思考超过 5 秒的事

2. 策虾 plan — 系统大脑

配置项值
模型anthropic/claude-sonnet-4-6
maxSpawnDepth2 (可 spawn depth-2 执行虾)
allowAgents["scribe", "calc", "forge", "audit"]
Sandboxoff
Workspace~/CC/

核心职责：收任务 → S/A/B/C/D 分级 → 出方案 → 派虾 → sessions_yield → 汇总 → 交付。D 级任务用 context: "fork" spawn 策虾分身并行。

3. 笔虾 scribe

文档 / PPT / BP / 论文 / PPTX / DOCX 全链路。模型 Sonnet 4.6，Docker sandbox。

4. 算虾 calc

数据分析 / 测算 / Stata / Excel / 市场模型。模型 Opus 4.7，Docker sandbox。

5. 工虾 forge

代码开发 / 架构设计 / 部署 / 调试。模型 Sonnet 4.6，Docker sandbox。

6. 审虾 audit

配置项值
模型anthropic/claude-opus-4-7
Sandboxoff
触发方式策虾 spawn (C/D级必调) + 用户直接唤出

职责：SALF 五维度审查（S20/A30/L20/F15/R15 ≥80通过）+ V6-TCS 评分 + 一票否决（数据造假/抄袭/敏感泄露）

7. 记虾 memory — 新增

配置项值
模型anthropic/claude-sonnet-4-6
Sandboxoff
Workspace~/.openclaw/workspace/
触发方式审虾抄送 + Cron(20:00/21:00/23:00) + 用户「记住这个」

五大职责：

  1. 重要信息归档 — 用户要求的→MEMORY.md / 可复用经验→TOOLS.md / 最佳实践→AGENTS.md / 行为偏好→SOUL.md
  2. 文件管理 — 清理冗余、控制字符预算、memory/按日期归档(超90天压缩)、目录清晰命名一致
  3. 模型量化追踪 — 维护「模型对比.md」按模型×任务类型交叉对比矩阵，供策虾做模型选择
  4. V6缺陷文档 — 系统性问题汇总(非个案)，分类：架构缺陷/模型瓶颈/流程断裂/文件混乱/安全风险。每条标注严重度P0-P2+触发频率+临时规避+V7建议。为V7设计直接输入
  5. 自改进闭环 — .learnings/ recurring≥3次→promote / 可封装→Skill / 每月进化报告

三、S/A/B/C/D 路由派虾

级条件策虾做法审虾
S门虾自己能答的回门虾「这个你自己答」否
A单一场景 / ≤2000字spawn 1只执行虾 → 汇总交付否
B标准交付 / 2000-8000字spawn 执行虾+要求V6-TCS自评 → 汇总否

四、V6-TCS 任务完成度评分标准（100分制）

设计原则：跨任务类型通用，足够苛刻。满分100 = 完美，非卓越不可得。

D1. 需求覆盖度 — 30分

分数标准
28-30完全覆盖显性+隐性需求。主动补充用户未提及但关键的边缘情况。用户觉得比预期多
24-27完全覆盖显性需求。大部分隐性需求触及。无遗漏
19-23覆盖所有显性需求。隐性需求未触及
14-18遗漏1项显性需求，或1项关键需求理解偏差
9-13遗漏2-3项显性需求，或核心需求理解偏差
0-3答非所问。大部分需求未满足

扣分触发：用户说了X但输出无X(-5/项)、暗示了Y但没识别(-3/项)、自作主张加用户没说的内容(-3/项)

D2. 输出正确性 — 25分

分数标准
23-25零错误。数据可溯源、逻辑完整无跳跃、代码可运行+边界测试通过、计算可复现
19-22无实质性错误。极少量不影响使用的边缘瑕疵
15-181处实质性错误（数据错误/逻辑矛盾/代码bug/计算偏差>5%/引用失真）
10-142-3处实质性错误
5-9多处错误，方向对但仍可挽救
0-4核心结论错误，需完全重做。存在数据造假嫌疑

一票否决：数据造假/大段抄袭/引用不存在文献→0分，记入V6缺陷

D3. 交付质量 — 20分

分数标准
18-20超出预期。信息密度极高、零废话、结构精炼、可直接交付第三方。读起来不像AI写的
15-17达到预期。简洁清晰，少量微调(<10%改动)。无明显AI套话
11-14基本可用。有明显冗余或粗糙，需20-30%改动
7-10勉强可用。大量AI痕迹（「在当今时代」「综上所述」「值得注意的是」），需>50%改动
0-2完全不可用。需要重写

扣分触发：「综上所述」/「值得注意的是」/「在当今时代」(-2/类)、emoji滥用(-1/个)、段落超8行(-1/处)、结论不先行(-3)

D4. 规范遵循度 — 15分

分数标准
13-15严格遵循所有规范。三线表参数/字体/字号/行距100%准确。引用一致
10-12遵循主要规范，1-2处小偏离（如字体设了但eastAsia没设）
7-9遵循了但执行粗糙（三线表线粗不一致、表注位置不对）
4-6多处规范偏离
0完全不符合规范。根本不知道有规范

D5. 效率与成本 — 10分

分数标准
9-10模型选择最优+路径无冗余+token效率极佳
7-8模型合理，路径基本高效，少量可优化冗余
5-6模型合理但路径有优化空间（串行可并行的子任务、重复读取）
3-4模型偏高（轻任务用Opus）或路径明显冗余
0严重浪费（重跑>3次、反复spawn同一任务）

总分等级

分数等级含义
95-100A+卓越。可直接对外交付。策虾无需修改直接给门虾
85-94A优秀。微调(<10%)后可用
75-84B良好。需局部修改(10-30%)
65-74C合格。需较大修改(30-50%)。审虾打回一次
50-64D不合格。需重做。记虾记录
<50F严重失败。打回重做+记入V6缺陷+策虾重新评估方案
