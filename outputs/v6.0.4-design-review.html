所有权铁律：每个文件有且仅有一个写入者。记虾是所有 workspace 文件和自身数据目录的唯一写入者。审虾只写进化周报.md。其他虾绝不直接写任何 workspace 文件——通过 sessions_send 发数据给记虾，记虾负责写。

1.2 记虾的工具权限（精确到白名单）

工具允许用途
read✓读取任意 agent workspace 文件
write✓写入任意 agent workspace 文件
edit✓局部编辑文件
bash✓文件操作（mv/cp/rm/mkdir）、grep 检查
sessions_list✓查看活跃 session
sessions_history✓读取任务 session 记录用于归档
sessions_send✓通知门虾/策虾/审虾
sessions_spawn✗记虾不派任务
browser✗不需要
canvas✗不需要
cron✗记虾被 cron 触发，不创建 cron

记虾 workspace = ~/.openclaw/（父级目录），sandbox: off。用绝对路径操作各虾的 workspace 子目录。

1.3 .learnings/ 数据流与写入责任

文件数据来源传输方式写入者
LEARNINGS.md 策虾（从任务交付后提取：执行虾自评 + 审虾打分 + 新发现的最佳实践） sessions_send(memory, "LRN: …") 记虾
ERRORS.md 执行虾遇到异常 → announce 给策虾 → 策虾转发记虾 sessions_send(memory, "ERR: …") 记虾
FEATURE_REQUESTS.md 门虾识别用户需求信号（「能不能…」「为什么不能…」） sessions_send(memory, "FEAT: …") 记虾

记虾是 .learnings/ 的唯一写入者。所有虾通过 sessions_send 发数据，记虾去重后写入。杜绝写冲突。

1.4 写冲突消除

文件写入者写入时间读者阅读时间是否安全
.learnings/*.md记虾21:00 + 实时(sessions_send)审虾22:00✓ 1h窗口
V6缺陷.md记虾23:00审虾22:00(次日)✓
memory/*.md记虾23:00审虾/策虾随时✓ 只读
进化周报.md审虾周一 09:00记虾周一 09:00后✓
SOUL/AGENTS/TOOLS记虾20:00(Cron) + 实时各虾随时⚠ 需锁

SOUL/AGENTS/TOOLS 的写锁机制：记虾在写任何 agent workspace 文件前，先检查该文件的上次修改时间。如果 5 分钟内被修改过→ 跳过本轮，等下次 Cron。这防止了实时 sessions_send 触发写入和 Cron 调度的碰撞。

1.6 MEMORY.md 指针校验

MEMORY.md 只存指针，不存内容。格式：

## 项目记忆
- Pegasus市场研究 → [memory/projects/pegasus-market.md]
- 食以司南BP → [memory/projects/shiyisinan-bp.md]
## 决策记忆
- 2026-05-20 确定V6采用7虾架构 → [memory/2026-05-20.md#决策记录]

记虾每月1日 09:00 执行指针校验（Cron）：

  1. 解析 MEMORY.md 中所有 → [path] 格式的指针
  2. 逐个检查目标文件是否存在
  3. 存在 → 检查最后修改时间
    • >90天未更新 → 指针后追加 [冷] 标记
    • ≤90天 → 正常
  4. 不存在 → 同路径搜索相似文件名 → 找到→更新指针 / 找不到→指针后追加 [已失效: YYYY-MM-DD]→ sessions_send 门虾通知用户
  5. 校验结果写入当日 memory/YYYY-MM-DD.md §7 文件健康度

1.7 Bootstrap 预算超限执行链路

记虾 20:00 Cron → 遍历7虾 workspace → 检查每份文件 char 数
  │
  ├─ 全部在预算内 → 记录「7/7 ✅」→ 无事
  │
  └─ 任一文件超限 → 触发修复链路：
        │
        ▼
      记虾 → sessions_send 策虾：
        「gate/SOUL.md 超限 202 chars（预算300，实际502）。
          当前内容：…(摘要)…
          请出精简方案。」
        │
        ▼
      策虾 → sessions_send 记虾（15min内）：
        「方案：删除第X条（已过时），合并第Y+Z条。预估精简后≈260 chars。」
        │
        ▼
      记虾执行：
        1. cp SOUL.md SOUL.md.bak.YYYYMMDD（备份）
        2. 按方案修改 SOUL.md
        3. wc -c 验证 ≤ 预算上限
        4. sessions_send 策虾：「gate/SOUL.md 已更新，旧版备份为 .bak.YYYYMMDD。请在下一次门虾任务中观察行为。」
        │
        ▼
      策虾（下次使用门虾时）→ 观察门虾行为是否正常
        ├─ 正常（1天内无异常）→ sessions_send 记虾 → 记虾 rm .bak
        └─ 异常 → sessions_send 记虾 → 记虾 cp .bak SOUL.md（回滚）→ 通知策虾重新出方案

1.8 V6缺陷.md vs ERRORS.md 的升级规则

判断条件归属操作
单次错误，不影响其他任务.learnings/ERRORS.md记虾归档
同一错误≥3次（跨任务/跨虾，30天内）V6缺陷.md（P2）记虾升级+通知审虾
单次错误但影响≥2个虾V6缺陷.md（P1）记虾立即升级+通知策虾
单次错误导致任务失败/数据丢失/熔断V6缺陷.md（P0）记虾立即升级+通知门虾告知用户
某虾持续性表现问题（V6-TCS连续5次<70）V6缺陷.md（P1）记虾在日记录中标记+审虾回溯

记虾 21:00 Cron 自动扫描：grep ERRORS.md 中最近30天的条目→按错误类型分组→统计频次→≥3次→升级到 V6缺陷.md。人工确认的不需要等3次（单次影响大即可升级）。
