Phase 0：Gateway 稳定性基础设施层 [V6.0.5 新增]

为什么需要 Phase 0：Openclaw 2026.4.x 系列存在 7 个已知崩溃/卡死根因。V6 的七虾架构完全依赖 Gateway 常驻运行——Gateway 崩了，门虾失联，策虾断链，所有 Cron 停摆。Phase 0 在装任何虾之前先把地基打牢。

0.1 稳定版本锁定

社区多位重度用户确认：2026.4.23 是目前唯一经过 7×24 验证的稳定版本。之后的所有版本（4.24-4.29）均引入了一个或多个崩溃/卡死问题。

# 安装指定版本
npm install -g openclaw@2026.4.23
openclaw gateway restart

# 禁止自动更新
openclaw config set update.autoCheck false
openclaw config set update.autoUpdate false

版本升级策略：在社区确认新版稳定（连续 7 天无 P0 问题）之前，锁定 2026.4.23。升级前必须 openclaw backup create + openclaw backup verify --latest。升级后必须 openclaw doctor --deep。保留上一个稳定版本的 npm tgz 到本地以便快速回滚。

[V6.0.6] 升级回滚触发规则：升级后进入 7 天观察期。观察期内触发以下任一条件 → 立即回滚到上一个稳定版本：

条件级别
1 次 P0 级别的 Gateway 崩溃（aegis 触发 L3/L4 修复）立即回滚
3 次 P1 级别异常（同一 agent 连续被打回 / 死信 pending>10条 / 质量断崖>20分 各计1次）立即回滚
日成本超出同级预算 200%（如 A 级均成本 >$0.10）评估回滚
用户主动要求回滚立即回滚

0.2 七项崩溃根因修复

#根因症状V6.0.5 修复
1 僵尸 Session 旧 session 文件在 Gateway 启动时重新加载 embedded runs → CPU 100%+ 记虾每日 02:00 Cron 清理 ~/.openclaw/agents/*/sessions/*.jsonl（保留当日）；每次 Gateway 重启前预清理
2 Compaction 死循环 空/已压缩上下文触发无限重新压缩，日志声称「已抑制」实际未停 所有 agent 设 contextTokens: 128000（从 32000 提高），避免触发阈值过低
3 Plugin 伪关闭 plugins.entries.X.enabled: false 不阻止加载。Discord plugin 即使 disabled 也在后台无限重试部署 slash commands 改用 plugins.allow 白名单：仅加载必需的 plugin（feishu、memory-qmd、cron、subagents）。其他一律不加载。[V6.0.6] 实施前验证：openclaw status --deep 确认实际加载的 plugin 列表与白名单一致，人工排查是否遗漏日志/健康检查/会话管理等非业务必需插件。
4 Node 堆无限增长 长对话 + 大上下文 → V8 heap 无上限 → GC 持续 thrashing → CPU 高 + 延迟飙升 launchd plist 设 NODE_OPTIONS=--max-old-space-size=1536（限制 1.5GB）
5 Plugin 重复解析 每条消息都重新 resolve 31 个 npm 依赖，耗时 1-16s+CPU 通过 plugins.allow 缩小插件集→减少依赖数。无根治方案（等上游修复），但缩小集→影响可控
6 chokidar v5 不兼容 2026.4.25 起 chokidar v5 默认导出变更 → ~60% plugins 静默丢失 → Gateway 不回消息 锁定 2026.4.23（chokidar 尚为 v4），无此问题
7 Mac App 覆写 config Mac App 周期性覆写 openclaw.json → 删除 gateway.auth → Gateway 拒绝启动 → launchd KeepAlive 重启循环 不使用 Mac App。全 CLI 操作。config 每日备份（记虾 Cron 03:00 → cp ~/.openclaw/openclaw.json ~/.openclaw/openclaw.json.bak.YYYYMMDD）

0.3 openclaw-aegis 守护配置

选型理由：三款社区守护工具（keeper / aegis / clawdoctor）中，aegis 最全面——11 种健康探针 × 4 级修复策略 × 8 通道告警 × 熔断保护。V6 的复杂性需要最强的守护。

# 安装
npm install -g openclaw-aegis

# 初始化（自动检测 Gateway 配置，生成 aegis 配置）
aegis init --auto

# 启动守护
aegis start

# 安装为 launchd 服务（开机自启，先于 Gateway 启动）
aegis install-daemon

aegis 11 项健康探针（每 10 秒）：

探针检查内容V6 影响
ProcessGateway 进程是否存活崩了→门虾无响应
Port18789 端口是否在监听端口挂→所有 agent 断连
HTTP/healthz 是否返回 200HTTP 层假死→消息进不来
Configopenclaw.json 是否有效 JSON5config 损坏→Gateway 启动即崩
WebSocketWS 连接能否建立WS 断→飞书 channel 离线
TUN模型 API 连通性不通→所有虾无法调用 LLM
MemoryNode 进程 RSS 是否超限OOM→Gateway 被系统 kill
CPUCPU 使用率是否异常100%→消息延迟暴涨
Disk~/.openclaw/ 磁盘使用率是否 >90%（含 inode）满→session 无法写入
Logsgateway.log 中是否出现已知崩溃模式提前发现→L2 修复
Channel飞书 WebSocket 连接状态断开→用户消息收不到

4 级修复策略：

级别触发条件动作耗时
L1 快速重启进程存活但 HTTP 无响应（假死）openclaw gateway restart~10s
L2 定向修复日志中检测到已知崩溃模式（僵尸session、compaction循环）执行对应修复（清理 sessions、调整 contextTokens）+ 重启~30s
L3 深度修复L2 修复后仍然异常，或 config 损坏openclaw doctor --fix --non-interactive + config 回滚到最近备份 + 重启~2min
L4 人工告警L3 仍然失败，或连续 3 次触发 L3停止自动修复。aegis 通过 Telegram/飞书通知用户。等待人工介入人工

0.4 macOS launchd plist（完整配置）

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>com.manton.openclaw-gateway</string>

    <key>ProgramArguments</key>
    <array>
        <string>/opt/homebrew/bin/openclaw</string>
        <string>gateway</string>
        <string>start</string>
    </array>

    <key>RunAtLoad</key>
    <true/>
    <key>KeepAlive</key>
    <true/>

    <!-- 崩溃后等待 15 秒再重启（防止快速重启循环） -->
    <key>ThrottleInterval</key>
    <integer>15</integer>

    <key>EnvironmentVariables</key>
    <dict>
        <!-- V6.0.5: Node 堆限制 1.5GB（防 OOM） -->
        <key>NODE_OPTIONS</key>
        <string>--max-old-space-size=1536</string>

        <!-- Gateway 认证 Token（防 Mac App 覆写 config） -->
        <key>OPENCLAW_GATEWAY_TOKEN</key>
        <string>FROM_KEYCHAIN_OR_ENV</string>
    </dict>

    <key>StandardOutPath</key>
    <string>/Users/manton/.openclaw/logs/gateway-stdout.log</string>
    <key>StandardErrorPath</key>
    <string>/Users/manton/.openclaw/logs/gateway-stderr.log</string>

    <key>WorkingDirectory</key>
    <string>/Users/manton</string>
</dict>
</plist>

# 安装 launchd 服务
cp /Users/manton/CC/projects/lark-claude-bridge/com.manton.openclaw-gateway.plist \
   ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/com.manton.openclaw-gateway.plist

# aegis 守护同理（先于 Gateway 启动）
aegis install-daemon  # 自动生成 plist 并加载

0.5 记虾新增的 Gateway 维护 Cron

时间执行虾动作
02:00 每日记虾清理僵尸 session：删除 ~/.openclaw/agents/*/sessions/*.jsonl（保留当日创建的文件）。记录清理数量到当日 memory/YYYY-MM-DD.md §4 异常事件
03:00 每日记虾备份 openclaw.json：cp ~/.openclaw/openclaw.json ~/.openclaw/openclaw.json.bak.YYYYMMDD。保留最近 7 天的备份
03:05 每日记虾清理过期备份：删除 >7 天的 openclaw.json.bak.*，删除 >30 天的死信归档
08:02 每日记虾Gateway 健康摘要：读取 aegis 日志 → 统计前一日探针失败次数、修复触发次数、最高修复级别。写入当日 memory/YYYY-MM-DD.md §7 文件健康度下新增「Gateway 健康度」子 section（错开 08:00 成本统计，避免 Cron 资源抢占）

0.6 Gateway 崩溃对 V6 的影响矩阵

崩溃场景门虾策虾执行虾审虾记虾aegis 响应
Gateway 进程死亡 ✕ 用户无响应 ✕ 所有进行中任务丢失 ✕ ✕ ✕ L1: 10s 内重启 Gateway
Gateway 假死(CPU 100%) ⚠ 延迟数分钟 ⚠ 延迟 ⚠ 超时 ⚠ 超时 ⚠ Cron 跳过 L2: 检测 CPU + 清理 session + 重启
Config 损坏 ✕ ✕ ✕ ✕ ✕ L3: doctor fix + 回滚 config 备份
连续 L3 失败 ✕ ✕ ✕ ✕ ✕ L4: 飞书/Telegram 通知用户

关键设计：aegis 在 Gateway 进程外运行（独立进程），不依赖 Gateway 本身的健康状态。Gateway 崩了→aegis 检测到→L1 重启。Gateway 假死→aegis 检测到→L2 修复。所有告警走 aegis 自己的通道（Telegram/飞书），不走 Gateway。
